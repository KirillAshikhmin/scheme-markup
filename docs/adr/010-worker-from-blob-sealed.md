# 010. Worker создаётся из Blob, запечатан и стерегётся таймером

Статус: принято · 2026-10-23

## Контекст

Страница работает по `file://` (ADR 001, 006). ADR 006 разрешает файлы рядом со
страницей, но Worker по `file://` из соседнего файла не создаётся. Сценарий
пользователя — чужой код: он может уйти в сеть или зависнуть.

## Решение

- Сборка делает второй бандл — движок для потока — и кладёт его в страницу
  строкой. Страница создаёт Worker через `Blob` и `URL.createObjectURL`.
- Первой строкой потока с него снимаются сетевые и порождающие двери: `fetch`,
  `XMLHttpRequest`, `WebSocket`, `EventSource`, `importScripts`, `indexedDB`,
  `caches`, `BroadcastChannel`, `Worker`, `SharedWorker`, `navigator` и другие.
  `HttpClient`, `Mail`, `SSH`, `Notify` — заглушки, которые пишут в журнал.
- Сторож на странице: пульс раз в секунду; нет ответа 3 секунды — поток
  уничтожается, поднимается новый из зеркала состояния, виновная привязка или
  сценарий выключается с пометкой «остановлен: завис».
- Нет Worker — движок работает в странице, и об этом сказано словами.

## Почему

- **Отдельный файл Worker рядом со страницей** — отвергнуто: по `file://` не
  создаётся, а веб-версия и файл должны вести себя одинаково.
- **Изоляция области скрипта (`with` и Proxy) как защита** — отвергнуто: она
  разводит сценарии между собой, но `this` в нестрогой функции отдаёт
  `globalThis`; от зависания она не защищает вовсе. Защиту даёт только поток.
- **Не искать виновного, гасить всё при зависании** — отвергнуто для случая,
  когда виновный находится: сторож гоняет пробные потоки по привязкам и гасит
  только найденную. Не нашёл — гасит все скрипты (`hungUnknown`).

## Последствия

- Строка потока живёт внутри страницы, поэтому сборка проверяет то, что иначе
  сломало бы страницу: `</script`, управляющие символы, строки вида `src=`/`href=`
  и строки, начинающиеся с `import … from`. Бандл не должен тянуть DOM-модули.
- Поиск виновника дорог: каждая зависшая проба добавляет 3 секунды.
- Печать снимает не всё: список снятого — перечень, а не доказательство
  отсутствия других выходов. Загруженный сценарий нельзя считать враждебным
  кодом под замком; запасной путь в странице не защищает вовсе.
- Поведение на `file://` проверено живым прогоном в Chrome; другие браузеры по
  документам не проверялись.
