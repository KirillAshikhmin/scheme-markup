# 032. Место связанной метки считает резолвер, mark.points не переписывается

Статус: принято · 2026-11-08

## Контекст

У связанной метки место, габарит, угол и высота должны следовать за вещью.
`mark.points` читают около ста двадцати мест, в том числе автопривязка
помещения и стены.

## Решение

Все читатели места идут через один резолвер `markPlace`: есть связь — место,
габарит, угол и высота берутся у вещи, нет — ответ равен прежнему. Точки метки
остаются такими, какими были, и правка вещи объект метки не трогает.

## Почему

- **Переписывать `mark.points` при каждой правке вещи** — отвергнуто: двигать
  вещь значило бы переписывать метки на каждом шаге, ломать «метка не двигается
  без руки» и нарушить G68 для старых объектов; отмена шага тоже вышла бы
  двойной.
- **Копировать место один раз при связывании** — отвергнуто: после первой же
  правки вещи метка и контур разошлись бы.
- **Дать каждому читателю свою арифметику** — отвергнуто: читателей десятки,
  и один забытый покажет знак там, где вещь уже не стоит.

## Последствия

- Резолвер — единственная дверь: новый читатель места обязан идти через
  `markPlace`, обойти его легко и не поймают ни тип, ни линтер, только тест.
- `mark.points` связанной метки — устаревшая запись «где знак стоял до связи»;
  при отвязке метка возвращается именно туда.
- Без связи ответ равен сегодняшнему, поэтому кадры несвязанных объектов не
  меняются ни на байт.
