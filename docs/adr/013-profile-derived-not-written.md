# 013. Профиль аксессуара выводится из типа, а не пишется в файл

Статус: принято · 2026-10-23

## Контекст

В объекте уже есть метки со типами из стартового справочника, а признака «тип из
шаблона» в данных нет — model.js от него сознательно отказался. Объект прежней
сборки обязан открываться без изменений (G68): ни метка, ни номер, ни подпись.
Профиль нужен каждой метке-аксессуару сразу.

## Решение

Пока человек профиль не правил, поля `type.device` в типе нет, а профиль
выводится чтением по коду типа (сравнение через `catalogRowKey`) и помечается
`derived`. Запись появляется только от явной правки человека у типа
или у метки (`mark.device` — частичные ключи поверх типа). Код типа, который
таблица не знает, даёт «неизвестно», а не догадку: такой тип попадает в список
«Типы без аксессуара» и ждёт решения.

Переименование кода типа без явного профиля **замораживает** выведенный профиль:
`updateType` записывает `{kind}` того, что выводилось под старым кодом. Смена
типа у метки снимает её свою настройку. Команда, записывающая то же, что и так
наследуется, возвращает тот же объект по ссылке.

## Почему

- **Записать профиль в каждый тип при открытии или миграцией** — отвергнуто:
  файл меняется от самого открытия, а старая сборка при пересохранении
  увидела бы незнакомые поля.
- **Признак «тип из шаблона»** — отвергнут ещё до этой фичи: он поехал бы в
  данные и врал бы при первой правке.
- **Применять догадку для своих типов сразу** — отвергнуто: профиль, угаданный
  неверно, молча делает метку не тем устройством; догадку человек подтверждает
  одним действием.

## Последствия

- Профиль зависит от кода типа и от сборки: изменение таблицы «тип → профиль» в
  будущей сборке тихо меняет выведенные профили старых объектов (явные не
  меняются).
- Переименование кода — единственная правка, которая обязана писать в файл
  без просьбы человека.
- Вызывающий код передаёт только изменённые ключи. Целый профиль, возвращённый
  из читателя, делал бы метку «своей» и дописывал `type.device` у выведенного.
  Команда теперь это распознаёт, но привычка остаётся правилом.
- Новое поле типа — в пяти белых списках (`addType`, `updateType`, шаблон
  пользователя, база типов, копирование); каждое — свой тест.
