# 014. Версия файла 6 ставится только объекту со сценариями или привязками

Статус: принято · 2026-10-23

## Контекст

`FORMAT_VERSION` равен 5 и поднимается тогда, когда прежняя сборка прочла бы
файл неверно. Слияние папки (`merge.js`) берёт только перечисленные в
`MERGE_ENTITIES` коллекции, а прежняя сборка о сценариях и привязках логики не
знает. Два теста жёстко ждут версию 5.

## Решение

Версия файла считается по содержимому: `projectFormatVersion` возвращает 6, если
в объекте есть хотя бы один сценарий или привязка логики, иначе 5.
`migrateProject` принимает 5 и 6, упаковка пишет вычисленную версию.
Профили типов и своя настройка меток версию не поднимают: они лежат внутри
типа и метки и сливаются вместе с ними.

## Почему

- **Всегда писать 6** — отвергнуто: прежняя сборка отказала бы каждому объекту,
  даже без единого сценария, хотя читала бы его верно.
- **Остаться на 5** — отвергнуто: прежняя сборка при слиянии папки молча
  выбросила бы коллекцию, которой нет в её списке. Честный отказ «объект из
  более новой версии» лучше тихой потери.
- **Пустые коллекции в объекте для ровной формы** — отвергнуто (G68): старому
  объекту ничего не дописывается от открытия.

## Последствия

- Первый созданный сценарий делает объект нечитаемым для прежней сборки.
  Удаление последнего возвращает версию 5.
- Тесты с жёсткой пятёркой остаются верными, но только для объектов без
  сценариев; для объекта со сценариями ждут шестёрку.
- Каждая будущая коллекция объекта решает ту же задачу заново: либо вносится в
  `merge.js`, либо поднимает версию по содержимому.
