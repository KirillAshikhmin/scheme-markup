# 026. Библиотека сценариев в продукте: ссылка на скрипт вместо исходника

Статус: принято · 2026-11-08

## Контекст

Исходник логических и глобальных сценариев в объекте раздувает файл и ссылку
(ADR 021), а у большинства объектов он один и тот же — из личной библиотеки
владельца. Правило G68: готовый объект не ломается.

## Решение

Скрипты библиотеки лежат файлами рядом со страницей, имя файла содержит
отпечаток текста, рядом реестр. Сценарий в объекте несёт ссылку (имя, версия,
отпечаток), а не исходник; версия формата 7. Старый объект переводится на
ссылку только если его исходник совпал с библиотечным побайтово; настроенный
своей рукой остаётся текстом. Файлы с отпечатком не удаляются и не заменяются
никогда. Объект остаётся на своей версии; новую библиотека лишь предлагает.

## Почему

- **Приблизительное узнавание** (по имени, по близости текста) — отвергнуто: оно
  подменило бы правленый заказчиком сценарий чужим текстом.
- **Автообновление до свежей версии** — отвергнуто: меняет поведение дома у того,
  кто его не просил.
- **Заменять файл по тому же имени** — отвергнуто: объект, закреплённый на
  отпечатке, остался бы без своего скрипта. Поэтому старые файлы живут вечно.
- **Хранить исходник и в файле, и по ссылке** — отвергнуто: «чистая ссылка»,
  исходник не дублируется.

## Последствия

- Объект с ссылкой без сети и без кэша работает без этого сценария: сценарий
  помечен, в журнале строка. Это сказано честно, а не скрыто.
- Каталог библиотеки только растёт.
- Формат 7: «Разметка» старой версии такой объект не откроет.
- Состав библиотеки собирается вручную из личного репозитория, сборка о нём не
  знает.
