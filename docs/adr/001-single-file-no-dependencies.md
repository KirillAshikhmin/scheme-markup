# 001. Ни одной внешней зависимости: один самодостаточный файл и свой zip

Статус: принято · 2026-09-15

## Контекст

Условие заказчика — дословно: «что бы без своего сервера\хостинга» и «Все данные
должны храниться локально в браузере». На вопрос, где сервису жить, он ответил:
«И файл, и GitHub Pages». Это два несовместимых по требованиям сценария сразу:
страница открывается двойным кликом с диска, где браузер запрещает почти всё
внешнее, и она же лежит по ссылке и должна работать офлайн после первого
открытия.

Отдельно заказчик описал формат страховки: «сохранить проект в файл (думаю зип
архив с схемами и всеми данными по меткам в своём текстовом формате (напрмиер
json))». Zip, то есть формат, который принято брать библиотекой.

## Решение

Весь исполняемый код проекта — свой. Сборка склеивает исходные модули и стили
в единственный HTML-файл; наружу не ведёт ни одна ссылка — ни на CDN, ни на
соседний скрипт, ни на шрифт. Никаких сторонних библиотек не подключается и не
вкомпилируется, включая zip: архив проекта пишется и читается собственным кодом
поверх браузерных потоков сжатия, а там, где их нет, — запасным путём «без
сжатия».

Отвергнуто:

- **Библиотека с CDN.** Ломает оба сценария разом: по `file://` внешний запрос
  не проходит, а офлайн по ссылке умирает на первом же обращении к сети.
- **Библиотека, вкомпилированная в сборку.** Офлайн переживает, но раздувает
  единственный файл, который целиком грузится при каждом открытии.
- **Свой бэкенд или хостинг с API.** Прямо противоречит требованию заказчика;
  вместе с ним отпадают аккаунты, совместная работа и облачное хранение.

## Последствия

Чем платим:

- Чтение и запись zip — наш код: заголовки формата, контрольные суммы, разбор
  чужого архива. Битый или посторонний файл мы обязаны распознать сами и
  отказать понятно, иначе пользователь получит мусор вместо проекта.
- Там, где браузер не даёт потокового сжатия, файл проекта выходит несжатым и
  заметно тяжелее — при планах в пару мегабайт каждый это видно сразу.
- Любая правка требует шага сборки. Собранный файл нечитаем в diff и
  обновляется только целиком: частичного обновления и кэширования по кусочкам
  не существует.
- Для будущих задач готовое взять неоткуда. Каждая такая задача — планы в PDF,
  сложная графика, распознавание — обойдётся в собственный код или в отказ от
  требования. Это цена, которую платит не эта сборка, а следующая.
- «Ни одного сетевого запроса после загрузки страницы» — постоянный критерий
  приёмки, а не разовая проверка: одна забытая ссылка на шрифт тихо возвращает
  проект в состояние «работает только онлайн».

Что получаем: файл можно переслать, положить на флешку, синхронизировать
облачным диском и опубликовать на статическом хостинге — это один и тот же
файл, и он не устаревает вместе с чьим-то CDN.
