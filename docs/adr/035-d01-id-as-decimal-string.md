# 035. D01: номер хранится десятичной строкой, а не числом JSON

Статус: принято · 2026-11-08

## Контекст

План допускал номер числом JSON: `17` короче и естественнее `"17"`.

## Решение

Код доказал: номер хранится десятичной строкой («17»). Счётчик
`project.counters["#id"]` — число, id сущностей — строки.

## Почему

- **Число JSON** — отвергнуто замером: сторожа `typeof id === "string"` стоят по
  всему коду (дом, сценарии, слияние, ссылка); настоящее число роняет около 600
  тестов в 85 файлах, строка-число роняет два.
- **Ослабить сторожей до «строка или число»** — отвергнуто: сторожа ловят
  настоящие ошибки (подмену id другой сущностью), а ослабление распылило бы
  правку по сотне мест без выигрыша для человека.

## Последствия

- Человек видит то же самое, адрес аксессуара тот же.
- Сравнивать номера по величине нельзя без перевода; порядок «по возрасту»
  придётся брать у счётчика или переводить явно.
- Число в чужом JSON (руками собранный файл) не будет принято как id.
