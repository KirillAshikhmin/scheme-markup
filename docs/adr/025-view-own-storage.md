# 025. У страницы просмотра своё хранилище

Статус: принято · 2026-11-08

## Контекст

База браузера общая на адрес сайта, а обе страницы лежат в одной папке. Объект
из ссылки при открытии получает новые идентификаторы и сохраняется.

## Решение

Просмотр работает в своей базе с теми же хранилищами, настройки показа лежат
там же. Объект хранится одним слотом: новый вытесняет прежний; тот же объект
по имени заменяется молча, другое имя — один вопрос.

## Почему

- **Общая база** — отвергнута: интегратор, открыв ссылку у себя, получил бы
  просмотренную копию в списке своих объектов, причём с переписанными
  идентификаторами, то есть новым объектом.
- **Общая база с пометкой «просмотр»** — отвергнута: каждый список и каждая
  выгрузка «Разметки» должны были бы помнить о пометке.
- **Список просмотренных объектов** — отвергнут: заказчику нужен последний, а не
  архив.

## Последствия

- Настройки показа «Разметки» и просмотра не общие: выбранную погоду на одной
  странице другая не знает.
- Прежний объект заменяется без возврата; ссылку придётся открыть заново.
- Проверять хранилище приходится в двух базах.
