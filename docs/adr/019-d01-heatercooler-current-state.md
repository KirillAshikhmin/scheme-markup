# 019. D01: у кондиционера в профиле есть `CurrentHeaterCoolerState`

Статус: принято · 2026-10-23

## Контекст

Таблица «тип → профиль» в спецификации давала кондиционеру `HeaterCooler`:
`Active`, `CurrentTemperature`, `TargetHeaterCoolerState`, пороги. План не
называл `CurrentHeaterCoolerState`. При таске 01, сверяясь со словарём
(`research/sprut-templates.md` §7), выяснилось: в HAP эта характеристика у
`HeaterCooler` обязательна.

## Решение

`CurrentHeaterCoolerState` добавлена в профиль кондиционера сверх строки
таблицы, строка таблицы в спецификации исправлена. Требование не меняется: D01
служит R24 и R27 (сервисы и характеристики — по образцу шаблонов Sonoff,
Yandex, Sber и словаря хаба).

## Почему

- **Оставить таблицу как написано** — отвергнуто: аксессуар с обязательной
  характеристикой HAP, которой в нём нет, расходился бы с шаблонами, по образцу
  которых заказчик просил его строить, и логический сценарий, читающий эту
  характеристику, получил бы пустоту.
- **Сделать её необязательной галкой в окне профиля** — отвергнуто: обязательное
  не должно зависеть от выбора человека; необязательными остаются яркость,
  цветовая температура, цвет.

## Последствия

- Плановый документ (таблица) перестал быть единственным источником профилей —
  код следует словарю, а таблицу пришлось подправить.
- Соседние характеристики кондиционера сдвинули свои `cid` в нумерации с 13.
- Поведение термостатов в имитации описано только для термостата: у
  кондиционера за целевым состоянием следует и текущее, но температура комнаты
  сама не меняется.
- Тот же приём — сверка с обязательными характеристиками HAP — нужен для любой
  новой строки таблицы.
