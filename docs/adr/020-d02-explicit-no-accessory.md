# 020. D02: «без аксессуара» для незнакомого типа записывается явно

Статус: принято · 2026-10-23

## Контекст

План: `setTypeDevice(null)` значит «без устройства», `undefined` — снять
правку. Команда, записывающая то же, что и так наследуется, не пишет ничего
(ADR 013). Для Щ, ВР и других известных не-аксессуаров выведенный профиль уже
«без аксессуара» — запись не нужна. Свой тип с незнакомым кодом выводится как
«неизвестно» и стоит в списке «Типы без аксессуара» (история 1.7).

## Решение

Код при ревью ветки (F1) доказал, что для типа с незнакомым кодом `null` не
совпадает с выведенным: его выведенный профиль — «неизвестно». Поэтому
`setTypeDevice(null)` у такого типа записывает «без устройства» явно,
`type.device = {kind: "none"}`. Решение человека хранится в данных; снять его
можно только `undefined`, и тогда тип вернётся в список.

## Почему

- **Считать `null` совпадением и не писать** — отвергнуто: тип остался бы в
  списке «Типы без аксессуара» навсегда, хотя человек уже решил. Спецификации
  это противоречит: «догадка не применяется сама», решение должно закрывать
  вопрос.
- **Отдельный список «отклонённых» типов в объекте** — отвергнут: ещё одно поле
  для того же факта, которое пришлось бы вести в сливаемых коллекциях и шаблоне.

## Последствия

- Только здесь выбор человека пишет в файл «пустоту», и файл объекта растёт на
  одну запись за каждый такой тип.
- «Без аксессуара», записанное явно, и «без аксессуара», выведенное по таблице,
  выглядят одинаково на экране, но живут по-разному: явное переживает
  переименование кода типа, выведенное исчезает вместе со своим кодом.
- Каждый вызывающий код обязан различать `null` и `undefined`; перепутать — значит
  вернуть тип в список или записать то, чего человек не выбирал.
