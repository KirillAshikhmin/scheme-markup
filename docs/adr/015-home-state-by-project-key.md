# 015. Состояние дома помнится в браузере, по постоянному ключу объекта

Статус: принято · 2026-10-23

## Контекст

Раунд 3 брифинга: состояние устройств «в браузере», как открытые двери и шторы,
в файл не уходит. Свои заготовки сценариев видны во всех объектах (раунд 4).
У объекта два идентификатора: `project.id` перевыдаётся при открытии файла
(`adoptLoadedProject`), `project.key` постоянный.

## Решение

Состояние дома хранится в настройках браузера отдельным ключом `simState`:
`{[project.key]: {values, at, running}}`, не больше 20 объектов, запись не чаще
раза в 0,5 с. Свои заготовки — отдельный ключ `scenarioTemplates`, общий для
всех объектов. В файл проекта и в выгрузки состояние не попадает.
Живое состояние не хранится в `project` (ADR 009).

## Почему

- **В файле проекта** — отвергнуто: каждый щелчок по выключателю был бы
  правкой: шаг истории, `updatedAt`, автосохранение, конфликт при слиянии папки
  с напарником.
- **Ключ `project.id`, как у памяти вида** — отвергнут: открыл свой же файл —
  `id` новый, дом сброшен. Решение «открыл свой файл, дом остался как был»
  требует постоянного ключа.
- **Слот общего места (`screenPlace`)** — отвергнут: он одиночный, на одну схему,
  ограничен 500 ключами и принимает записи только от экрана-владельца.

## Последствия

- Состояние не едет вместе с файлом на другую машину; там дом начнёт с
  умолчаний.
- Копия файла несёт тот же `key`, поэтому копия и оригинал на одном браузере
  делят одно состояние.
- Двадцать объектов — потолок: двадцать первый вытесняет самый старый.
- Задержки и таймеры не сохраняются: после перезагрузки страницы они сброшены,
  в журнале так и написано.
- Кнопка «Сбросить дом» — единственный путь вернуть умолчания.
