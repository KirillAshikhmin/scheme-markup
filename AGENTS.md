# Разметка электроточек: что это и как с этим работать

Памятка агенту, который видит проект впервые. Полные правила сборки — в
`/AGENTS.md` (корень репозитория), устройство и доводы каждого решения — в
`.autopilot/scheme-markup/interfaces.md`.

Та же памятка живёт **страницей на сайте**: исходник `web/guide.html`, в сборке
`dist/guide.html`, адрес — рядом с самим сервисом (`…/scheme-markup/guide.html`).
Это один рассказ в двух видах, и расходиться им нельзя: правишь этот файл —
открой и страницу. Что сверяется машиной — список команд оснастки, числа
встроенных каталогов и правило G68 — держит `test/guidePage.test.js`; остальное
сверяется глазами.

## Что это

Браузерный инструмент инженера-проектировщика умного дома: на план квартиры
ставят **метки** электроточек (свет, выключатели, розетки, климат, сеть,
датчики), чертят стены с проёмами, обводят помещения, смотрят дом в объёме и
выгружают это в документы.

Одна статическая страница — ни сервера, ни установки, ни интернета. Объект
живёт в браузере (IndexedDB), переносится файлом — zip с `project.json` внутри.

## Что в нём можно делать

**Схема** — план с метками. Справочник типов (код, знак, цвет, размеры),
группы, связи «что чем управляется» с номерами каналов, фильтры, поиск,
автонумерация, помещения контурами, линейные метки (ленты, треки, карнизы).

**Чертёж** — стены в миллиметрах, проёмы из каталога на 17 видов (двери
распашные, двустворчатые, сдвижные, гармошки, портальные; окна одинарные,
двойные, тройные, балконные, витраж; арка, проём; ворота распашные, сдвижные,
роллетные, секционные), вещи из каталога на 59 предметов, развёртки стен
участками между углами, точка привязки схем и наложение чужого чертежа.
Высота — общая у схемы, своя у помещения (только поднимает его стены) и своя
у стены (`wall.heightMm`, главнее всех; 0 — стены нет, остаётся пол). Стену
делят на отрезки по примыканиям и границам помещений (`splitWall`). Потолок
помещения пропадает сам, если оно выходит на улицу стеной ниже этажа, и
ставится рукой (`room.hasCeiling`).

**Объём** — дом в три измерения: ходьба от первого лица и свободная камера,
двери и шторы открываются, этажи стопкой, двусветные пространства, настоящая
астрономия солнца и луны с пятнами света в комнатах, фон с городом и природой.

**Выгрузки** — PNG схемы с легендой, лист по ГОСТ с рамкой и штампом, таблицы
в CSV, печать, zip всех схем.

## Как получить данные из объекта

**Не пиши свой разбор zip и свой скрипт браузера — всё это уже есть.**

```
node tools/scheme.mjs <команда> <объект.zip> [ключи]
node tools/scheme.mjs --help
```

Без браузера, за доли секунды: `info`, `marks`, `types`, `rooms`, `drawing`,
`walls` (развёртки словами), `links`, `equipment`, `summary`.
Через браузер (поднимает своё и закрывает за собой): `plan-png`, `gost-png`,
`elevation-png`, `volume-png`.

Вывод — `--format json|csv|md|tsv`. Для техдокументации: `summary --format md`
даёт готовые таблицы по помещениям, типам, этажам, длинам линейных меток и
перечень оборудования.

```bash
node tools/scheme.mjs info "tmp/объект.zip" --format md
node tools/scheme.mjs marks "tmp/объект.zip" --format csv --out метки.csv
node tools/scheme.mjs walls "tmp/объект.zip" --wall АБ
node tools/scheme.mjs volume-png "tmp/объект.zip" --no-roof --out ./
```

**Правило, которое держит этот инструмент честным:** он ничего не считает сам.
Площади, длины, габариты, таблицы и листы берутся у модели страницы — иначе
документ и экран разошлись бы в числах. Единственное своё — площадь помещения
в квадратных метрах, и без калибровки она пустая.

## Команды

```bash
npm test          # node --test "test/**/*.test.js"; зависимостей нет ни одной
npm run build     # собирает dist/ целиком: страница + шрифт + файлы веб-версии
```

Node ≥ 22. `npm install` ставить нечего: `npm ls --all` печатает `(empty)`.

## Что надо знать, прежде чем править

- **Главное правило заказчика (G68):** готовые объекты не ломаются. Любая
  правка формата требует миграции и теста на старом файле. Догадку
  **показывают, а не применяют**.
- **Каталоги встроенные:** вещи чертежа и виды проёмов расширяются только
  сборкой. Справочник типов меток, наоборот, расширяет человек.
- **Ванильный JS**, ES-модули, только именованные экспорты. `build.js`
  склеивает всё в один IIFE — библиотек не завозить.
- **Строки интерфейса — в словаре** (`src/strings.js`), не в компонентах.
- **Правку CSS зелёный прогон не подтверждает:** тесты ищут в склеенном тексте
  строки, структуру не разбирают. Трогал стили — открой страницу глазами.
- **`tmp/` — настоящие объекты заказчика**, каталог в `.gitignore`. Ничего
  оттуда не коммитить, имена помещений в отчётах не называть.

## Живой прогон

Снимки на настоящем объекте — часть приёмки. Правило среды, купленное пятью
испорченными прогонами:

- расширение Claude-in-Chrome до `127.0.0.1` **не достаёт вовсе**;
- у chrome-devtools MCP «выбранная страница» **одна на всех агентов** и
  переставляется между твоими вызовами — уводит чужие вкладки;
- **перезагружать страницу через CDP нельзя** — у неё `beforeunload`,
  отрисовщик виснет намертво; закрывать вкладку и открывать новую.

Поэтому: свой сервер на своём порте, свой Chrome с отдельным профилем и своим
портом отладки, охрана `if (!location.href.includes('<свой порт>')) return;` в
каждом внедряемом скрипте, файлы прогона с номером своего таска.

Готовый пример такого моста — `tools/schemeSheets.mjs`: он поднимает сервер и
Chrome, рисует картинки и закрывает за собой всё, в том числе при ошибке.

## Где что лежит

| | |
|---|---|
| `src/` | страница: `model.js` (все правила объекта), `render.js` (геометрия и рисование), `canvas.js` (план), `volume.js` (объём), `panels/` (колонки и окна), `exporter.js` (выгрузки), `strings.js` (весь текст) |
| `tools/` | оснастка: `scheme.mjs` и мост к браузеру |
| `web/` | файлы веб-версии рядом со страницей: служебный скрипт офлайна `sw.js` и памятка страницей `guide.html` — оба едут в `dist/` как есть |
| `test/` | прогон; чистые швы покрыты, DOM и холст — нарочно нет |
| `dist/` | то, что публикуется на GitHub Pages: собранная страница целиком, шрифт, файлы веб-версии и памятка; лежит в git |
| `.autopilot/scheme-markup/` | требования (`manifest.md`), договор модулей (`interfaces.md`), тикеты, вопросы к владельцу |
