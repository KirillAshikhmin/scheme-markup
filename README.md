# Разметка схем

Метки на планах помещений: план этажа, цветные метки с обозначениями (Т1, В3, Р7),
таблица меток и выгрузка в PNG, CSV и на печать. Статическая страница —
ни сервера, ни установки, ни интернета.

- Собрать: `npm run build` → папка `dist/`: страница `index.html`, её файлы
  (чертёжный шрифт в `assets/`) и файлы веб-версии — манифест установки, значки
  и служебный скрипт. **Переносить и выкладывать нужно папку целиком.** Код и
  стили лежат внутри страницы, на чужие сайты и CDN не ведёт ни одна ссылка.
- Проверить: `npm test`.
- Нужен Node ≥ 22. Зависимостей у проекта нет ни одной.

## Где живут данные

Объекты, схемы и метки хранятся **в браузере той машины, где вы работали**
(IndexedDB), а не на сервере. Второй экземпляр той же работы — **файл проекта**:
кнопка «Сохранить в файл» отдаёт `<объект>-<дата>.zip` с `project.json`,
планами и `README.txt` внутри; «Открыть файл» возвращает объект обратно —
на этом же или на любом другом компьютере.

Перенос между машинами, передача коллеге и страховка от почищенного браузера —
это всё файл проекта. Привычка простая: закончили работу — «Сохранить в файл».

## Три способа разместить страницу без своего сервера

### 1. Файл на диске (двойной клик)

Скопируйте папку `dist/` куда угодно и откройте в ней `index.html` двойным
кликом. Работает офлайн, ничего настраивать не нужно.

Папку — целиком: рядом со страницей лежит её чертёжный шрифт. Один `index.html`
без соседей тоже откроется и будет работать, но подписи нарисует обычным
шрифтом и ничего об этом не скажет.

Ограничения:

- **Хранилище браузера по `file://` есть не везде.** Одни браузеры дают
  странице, открытой с диска, своё хранилище, другие — нет; проверять список
  версий бесполезно, он меняется. Если хранилища нет, страница скажет об этом
  строкой вверху сама и продолжит работать **в памяти вкладки**: закрыли
  вкладку — работа пропала, если не выгрузили её в файл. По `file://`
  «Сохранить в файл» стоит считать не страховкой, а способом сохранить.
- Автосохранение в папку по `file://` недоступно: браузер не даёт странице с
  диска доступ к файловой системе. Кнопка «Сохранять в папку» об этом скажет.
- Ссылку коллеге не дать — только саму папку (архивом).

### 2. GitHub Pages (ссылка)

Страница по `https://`, открывается с любого устройства. Доступны все
возможности, включая автосохранение в папку (там, где браузер умеет File System
Access), **установку приложением** и работу без сети (см. ниже).

Ограничения:

- Репозиторий с Pages по умолчанию **публичный** — сама страница не содержит
  ничьих данных, но не выкладывайте туда планы заказчиков.
- Новая версия страницы — это новый коммит: выложить «по-быстрому» из браузера
  не получится.
- Данные всё равно лежат в браузере каждого, кто открыл ссылку: общей базы
  у страницы нет, обмен — файлом проекта.

**Три шага:**

1. `npm run build`, скопировать **всё содержимое `dist/`** в корень нового
   репозитория на GitHub и закоммитить. Сама страница — `index.html`; рядом с
   ней папка `assets/` с чертёжным шрифтом, без которой подписи выйдут обычным
   шрифтом, и `manifest.webmanifest`, `icon.svg`, `icon-maskable.svg`, `sw.js` —
   они нужны только для установки и работы без сети.
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from
   a branch**, ветка `main`, папка `/ (root)` → **Save**.
3. Через минуту-две страница открыта по `https://<логин>.github.io/<репозиторий>/`.
   Обновление — тот же путь: пересобрать, заменить файлы, закоммитить.

#### Установка приложением

На странице, открытой по `https://`, браузер сам предлагает установку: в Chrome
это значок в адресной строке или пункт «Установить приложение» в меню, на
Android — «Установить приложение», на iPad и iPhone — «Поделиться» → «На экран
„Домой“». Установленное приложение открывается своим окном без адресной строки,
со своим значком, и вертикально, и горизонтально.

Работает без сети: последняя открытая страница остаётся в браузере, и на объекте
без интернета приложение откроется тем же значком. Данные при этом не
кэшируются — они и так лежат в браузере, а не в сети.

**Новая версия доезжает сама.** Страница всегда берётся сначала из сети: есть
интернет — человек видит свежую сборку с первого же открытия, и ждать ничего не
нужно. Из памяти она достаётся, только когда сети нет. Старая копия при этом
сносится: двух версий рядом не живёт.

Со страницы, открытой с диска (способы 1 и 3), установка не работает — это
ограничение браузера, а не сборки: `file://` не отдаёт странице ни манифест, ни
служебный скрипт. Офлайн там и так полный.

### 3. Папка синхронизируемого облачного диска

Положите папку `dist/` в Яндекс Диск, Дропбокс или iCloud Drive — она сама
окажется на всех ваших машинах, открывать так же, двойным кликом по
`index.html` внутри.

Ограничения:

- Это по-прежнему `file://` со всеми ограничениями первого способа
  (хранилище может быть недоступно, автосохранение в папку — нет).
- Публичная ссылка облака обычно **скачивает** файл, а не открывает страницу:
  для коллеги это способ передать файл, а не адрес сервиса.
- Синхронизируется только сама страница. Объекты и метки живут в браузере той
  машины, где вы работали, — переносите их файлом проекта.

## Автосохранение в папку

Если браузер умеет File System Access (нужен `http(s)`, то есть способ 2),
нажмите «Сохранять в папку» и один раз укажите папку. Дальше объект сохраняется
туда сам после каждой правки, с небольшой задержкой; имя файла —
`<объект>-<код объекта>-<код браузера>.zip`. **Файл на объект один**: он
переписывается, а не заводится заново каждый день — когда его записали, видно
по времени файла. Код объекта в имени нужен, чтобы два объекта с одинаковым
именем не затирали друг друга; код браузера — чтобы ваш файл не спутался с
файлом коллеги, когда папка общая. Переименуете объект — снимок поедет за новым
именем, а прежний файл останется лежать; страница о нём скажет и предложит
удалить. Разрешение запоминается: при следующем запуске страница попросит
подтвердить его одной кнопкой, а не выбирать папку заново.

**Работа вдвоём.** Положите папку в общее облако или WebDAV — у каждого свой
файл, и правки соседа приезжают в ваш объект сами, слиянием. Код браузера
заводится один раз и хранится там же, где данные (в этом браузере, на этой
машине); в объект и в файл, который отдаёт «Сохранить в файл», он не попадает.
Одинаковый объект у двоих — не беда: файлы всё равно разные, а значит, никто не
пишет поверх чужой записи.

Если вы вели объект в папке раньше, там могут лежать снимки под прежними
именами — с датой (`<объект>-<дата>-<код объекта>.zip`, по файлу на каждый день
работы) или без кода браузера. Они не потеряны и в объект не вмешиваются:
страница узнаёт их как свои, принимает как отправную точку, показывает списком и
удаляет только по вашей просьбе. Дата осталась в имени того файла, который
отдаёт кнопка «Сохранить в файл»: это копия «на память», и там она к месту.

Там, где так нельзя, в шапке видно, когда вы в последний раз выгружали объект
(«в файл выгружено: 3 дня назад»), а вкладка с несохранёнными правками
переспросит при закрытии.

## Как печатать лист по ГОСТ, чтобы сошлась линейка

Лист с рамкой и основной надписью выверен в миллиметрах: на A4 рамка — ровно
185 × 287 мм, основная надпись — 185 × 55 мм. Чтобы эти миллиметры дошли до
бумаги, печатать надо **скачанный PNG**, а не вкладку браузера.

1. В окне выгрузки поставьте отметку «Лист по ГОСТ» и нажмите **«Скачать PNG»**.
   Кнопка «Печать» тоже работает, но браузер печатает со своими полями и ужимает
   лист — линейкой такой отпечаток мерить нельзя.
2. Откройте файл обычной программой просмотра картинок («Просмотр» на macOS,
   «Фотографии» или Paint на Windows) и печатайте из неё.
3. В окне печати выберите бумагу **A4** и ориентацию, как у листа, а масштаб —
   **ровно 100 %** («Фактический размер», «Actual size»). Снимите «Подогнать под
   размер страницы» / «Fit to page»: именно она и ужимает чертёж.
4. Поля поставьте наименьшие. У рамки по ГОСТ до обреза всего 5 мм, а печатать
   ближе 4–6 мм к краю умеет не каждый принтер — если внешняя линия рамки
   срезалась, это предел принтера, а не ошибка чертежа.

Проверять удобнее всего по самой рамке: ширина между её боковыми линиями —
185 мм, высота на книжном A4 — 287 мм, основная надпись в углу — 185 × 55 мм.

Разрешение листа записано в самом файле (300 dpi при множителе 2×), поэтому
программа печати знает настоящий размер и не обязана гадать. Файлы, выгруженные
прежними сборками, разрешения не несут — их лучше выгрузить заново.

## Чёрно-белая печать

Отметка **«Чёрно-белый режим»** в окне выгрузки рисует лист сразу под
чёрно-белый принтер: знаки, подписи, связи и контуры помещений — чистой чёрной
тушью по белому, заливки помещений нет, план схемы обесцвечен. Это не то же
самое, что отдать цветной лист драйверу принтера: тот переводит цвет в серый по
яркости, и синий со светло-зелёным садятся в соседние оттенки, а светлая заливка
комнаты пропадает вместе с частью рисунка.

Такая же отметка стоит в окне выгрузки таблицы — и это **одна и та же
отметка**: подняли в одном окне, она поднята и в другом. Принтер у вас один,
и решение «печатаю на чёрно-белом» тоже одно. На листе таблицы пропадает
цветная полоска категории слева у строки (без цвета все полоски одинаковы и
ничего не говорят) и чернеет заголовок разбивки; строки при этом не
съезжают — чёрно-белый лист ложится на прежний колонка в колонку. Категорию
строки по-прежнему видно по её обозначению и колонке «Тип», а в справочнике
типов цвет категории написан словами: «Свет · синий (#1F6FEB)».

Отметка работает и вместе с «Листом по ГОСТ», и отдельно, и на «Все схемы
(zip)», и на кнопке «Печать» — в том числе при печати таблицы прямо из
браузера: предпросмотр в окне выгрузки сразу показывает, что ляжет на бумагу.
Она **ничего не меняет в объекте**: цвета категорий и помещений остаются
прежними, на экране и в следующей цветной выгрузке всё как было.

Цвет на схеме означает категорию, а знак — тип, и один знак носят несколько
типов из разных категорий (ночник и выход канализации, например). Без цвета
такие знаки станут одинаковыми, и окно выгрузки пересчитывает это для **вашего**
листа и называет поимённо рядом с отметкой. Знаки при этом не меняются: читать
их придётся по подписи — «Н1» и «КН1».
